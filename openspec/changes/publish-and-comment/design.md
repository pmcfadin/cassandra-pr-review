## Context

The report model is embedded in each rendered report (`site.read_model`). `gh` is logged in as the
owner (pmcfadin). Comments are public on apache/cassandra, so the tool must never double-post, never
link a stale report, and never post without an explicit `--post`.

## Decisions

### D1. Comment body
```
<!-- cassandra-pr-review:report pr=<N> head=<sha> -->
**Automated review report** for <head short sha>: **<verdict label>** · triage <rating>
<one line: N must-fix issues from the code review panel, or "no code review run">

- <reason 1 title>: <summary>   (up to 5, contributor items first, as in the report)

Full report: <pages url>
<italic footer: advisory, generated by cassandra-pr-review <version>; committers decide>
```
Plain markdown, at most ~1,500 characters; reasons are truncated with an ellipsis.

### D2. Find and update
`gh api repos/apache/cassandra/issues/<N>/comments --paginate` and look for the marker in a comment
by the logged-in user (`gh api user`). Found → `PATCH .../issues/comments/<id>`; not found → `gh pr
comment <N> -R apache/cassandra --body-file`. Record `{comment_id, url, head, posted_at}` in
`.work/pr/<N>/comment.json`.

### D3. Guards
Before posting: the local report's head sha equals the PR's current head (from a fresh `gh pr view`);
the Pages URL returns 200 and its embedded model has the same head sha; the comment differs from
the last posted one (otherwise "unchanged", no API write). On a TTY, prompt "Post to apache/cassandra
#N as <login>? [y/N]"; without a TTY, require `--yes`.

### D4. Testing
All `gh` calls go through one runner function, replaced by a fake in tests. No test touches the
network.

## Risks / Trade-offs

- [Public noise] → one comment per PR, edited in place; dry run by default.
- [Stale link] → head sha guard on both the local and the published report.
